# slicer

*Started 19 October 2026 on Prayas's word: "start afresh from rai base". It replaces the prompted reader in `../models/`, which on the same day was shown to choose by an option's place in the list (13 of 16 answers changed when the options were reversed).*

The slicer takes any narration of a system and one syntax keyword (`board-game`, `record`, `personhood`, `framework`, `life`) and fills that syntax's boxes. It is a reader trained from rai's base, deepset's MiniLM taught SQuAD 2.0 (`deepset/minilm-uncased-squad2`, CC-BY-4.0, from Microsoft's MiniLM, MIT), with rai's recipe (Koher's `rai/train.py`). It points and never writes: for each option of each box it either points at the sentence that shows that option or points at nothing. Code then decides. An option counts only above a line set so that no wrong pointing in the threshold rows clears it, and a box that holds one option is decided only when exactly one option clears the line. Anything else is undecided.

The question put to the reader for each option is the syntax's own wording: the box's name, the option's name and the option's description, read from `../site/<keyword>.json`. Nothing new is written for it.

## Data

`data/rulebooks/` holds 100 whole rule texts for invented board games (20 October 2026), each in the shape of boardgameBuilder's 47 (an introduction and steps; at five to ten sentences, shorter than most of the 47, which run to about twelve), with each box that a sentence shows labelled by pointing at that sentence. They were written after the first run showed the reader unsure on real rule texts. Every option has at least two of them, most three or more. Writing them showed a pull towards copying the test: nineteen first drafts were classic games that are among the 47 (Nim, Hex, Pig, Cheat, Liar's Dice, Senet, Sprouts and others) and were replaced with other mechanisms before anything trained. Four in five rule texts train (three times over), every fifth sets the threshold, and only the boxes labelled in a rule text are asked of it.

`data/sentences/` holds eight sentences for every option of every syntax (1,056 in all) and some neutral sentences, written by Claude Code on 19 October 2026 under Prayas's word (*"you can write training data"*). `build_rows.py` makes narrations from them in code, so every label is known by construction. Six sentences of each option train, and the other two build the threshold rows, which training never sees. The build stops if an option has too few sentences, if a sentence names an animal product (rai's word list), or if a sentence shares six words in a row with one of boardgameBuilder's 47 rule texts. Those 47 texts, with Prayas's own labels, are the test (`build_test.py`), and nothing trains on them.

## Running

```
python3 build_rows.py && python3 build_test.py
bash run-mac.sh                                   # three seeds, averaged, the line, the test
python3 slicer.py slice runs/soup board-game < narration.txt      # any keyword; each syntax uses its own line
```

## First run, 20 October 2026

Three seeds (7, 1, 2) of 47,600 rows, averaged. The line, set on the threshold rows, came out at 21.6, held there by one confident wrong pointing in personhood (*language: the person* where the answer was nothing); 99 of 703 answered threshold rows cleared it. On the 47 games every one of the 259 labelled boxes was undecided, because no margin on a real rule text reached 21.6 (the highest was 20.4). Below the line the reader does read: his option ranked first in 110 of 259 boxes (about one in ten by chance), and the top tenth of his options' margins (9.3 to 20.4) sits above all but one other option (highest 12.9). What it lacks is confidence on real text: it was trained on one clean sentence per option, and rule texts spread an option over steps and leave much unsaid. The next change, alone: training narrations written as whole rule texts in the shape of the 47, with the line set on held-out texts of the same kind.

**One line per syntax (20 October 2026).** A narration is always sliced within one syntax, so each syntax now has its own line, set on its own threshold rows. On the first run's model this alone moved the board-game line from 21.6 to 12.71 and the 47 games from 0 decided to 11 right, 1 partly, 2 wrong and 245 undecided of 259 (14 complete games: 6, 1, 0, 77). That is the matched figure the second run, with the rule texts, is compared against. The first run is kept in `runs-first/`.

Thirty go at the boxes the second run never decided (player interaction, theme, chance or skill, information visibility, simulation); thirty carry several options each. They followed a try with five new game ideas from `/new-idea` (run `cacd959c`): the second run decided three boxes across the five, all right (*hidden hands*, *take turns*, *roll and move*), and missed options stated outright (*race to finish*, *tile placement*, *fully cooperative*, *keep the game going*). **Thirty personhood accounts** (`data/rulebooks/personhood-1.json`): a piece of work told in four sentences, one per part, with the holders mixed so that *the person* holding the language is told apart from *the person* holding the intent. They are built from one sentence per holder per part, so they teach the parts in few wordings; personhood's threshold, set on held-back accounts in the same wordings, will read better than its reading of new text. The second run is kept in `runs-second/`.

## Fourth run: the plan from decomposition theory, 20 October 2026

From `../notes/decomposition-strategy.md`, on his word (*"make a plan to improve syntax model based on this and do"*), the reader kept at rai's 33M base.

1. **Cross-consistency pairs** (`consistency/board-game.json`): 18 pairs of options that cannot both hold, drafted by Claude Code from the options' descriptions, marked unadopted, his to strike or add to. None of his 47 labelled games holds both of any pair. `slicer.py` refuses a slice that decides both: both boxes undecided, the clash named. On the third run it removed Nim's *take turns* with *no turns* (2 partly to 1) and changed nothing else: the three wrong answers are each the only decision in their game, so no pair can catch them. Pairs bite as coverage rises.
2. **The passage first**: the box asked as a whole (`box_question`, the box's own name and description) to find where the narration speaks of it, then the options asked of that passage. Untrained (`passage_test.py`) it did worse: 12 right, 2 partly, 7 wrong on the third run, against 45, 1, 3 reading whole texts, since the reader had never been asked a box's question. The fourth run's one change is box rows: each box asked of every narration, answered by the sentence that shows one of its options or by nothing (7,936 rows; option rows unchanged byte for byte). `slicer.py threshold` now also sets a box line per syntax.
3. **The order of decisions** (`decision_order`): boxes ordered by how many cross-box pairs touch them. With the draft pairs: player interaction, victory condition, core mechanic, chance or skill, information visibility, theme, timing, simulation. It follows the pairs, so it is as adopted as they are.
4. **Spoken of, no option fits**: when the box's question clears the box line but no option clears its line, the box says so and quotes the passage; such boxes are the evidence that a syntax may lack an option. Needs the fourth run's trained box questions.
5. **Relabel ten games** (`relabel-10.md`): ten of the 47 by code, his earlier labels left out, for him to fill from the texts alone.

**The fourth run's result (`runs/`, 21 October 2026, 00:53).** Option lines: board game 13.03; box line 20.09. On the 47 games, reading whole texts with the draft pairs: **34 right, 0 partly, 0 wrong, 225 undecided** (14 complete games: 10, 0, 0, 74), against the second run's 29, 1, 0 and the third's 45, 1, 3. Training the box questions beside the options sharpened the whole-text reading. The passage step itself, now trained, still did worse than reading the whole text (29 right, 1 wrong at its own line of 15.77), so options are read from the whole text and the box questions serve move 4. Move 4 fired on 2 boxes across the 47 games, both boxes he labelled, so those are the reader's misses, not gaps in the syntax. On the five ideas: three boxes, all right (*hidden hands*, *take turns*, *most points*). This run is the water-tight one in use; the second and third are kept in `runs-second/` and `runs-third/`. During seed 2 the Mac slowed to a fifth of its pace while another session had Ollama's `qwen3.5:4b` loaded (3.8 GB, swap nearly full), and recovered when the model unloaded.
